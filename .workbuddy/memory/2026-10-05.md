  **依赖决策**：GeoPackage 就是带规范表的 SQLite 库，而项目已为桌面版元数据库引入纯 Go 的 `modernc.org/sqlite`（`internal/localdb`，go.mod 里本是 indirect）→ **复用它不增加任何二进制体积、也不需要 cgo**，保住了三平台交叉编译。只读打开用 `file:<path>?mode=ro`（不在用户数据旁生成 -wal/-journal）。

  **安全**：表名/列名来自用户文件，进入 SQL 前一律 SQLite 标准双引号转义（内部引号翻倍）+ 拒绝含 NUL/超长——**不做白名单**（合法 GeoPackage 允许中文表名），但杜绝拼接注入。整型主键（fid）只作要素 ID、不进属性。注册中途失败（如某个表的坐标系不支持）会**回滚已建图层与数据源**，不留半注册状态。

  **关键设计取舍**：
  1. **从 WKT 解析投影参数，而不是硬编码 EPSG 带号表**——WKT 自带中央经线、尺度因子、假东假北、椭球参数，照它算最准，还天然覆盖非标准中央经线与自定义坐标系；硬编码带号表既臃肿又必然漏。
  2. **基准按事实判断**：CGCS2000 与 WGS84 差在厘米级 → 可直接等同（按基准名关键词 + 椭球参数比对双重兜底）；其他基准（北京54/西安80）若 WKT 带 TOWGS84 就走七参数，**没带就明确拒绝**——静默当 WGS84 会引入 50~150m 系统性偏差。
  3. **二维数据做基准转换按 h=0**（通行做法），但必须在提示里写明，让用户知道这个前提。
  4. 换算在**解析阶段**完成，产物坐标系记为 4326；新增 `effectiveSRID()` 保证图层元数据报的是**换算后**的坐标系——照抄源码（如 4547）会让下游按"米"解释经纬度，出图必然错位（GeoPackage 的 DetectGeometry 与 ReadGeoPackageTable 必须用同一套判定，测试专门锁了这一点）。
  5. Web Mercator 的变体名（ESRI `Mercator_Auxiliary_Sphere`、OGC `Popular_Visualisation_Pseudo_Mercator`）在 WKT 里往往**不带 EPSG 权威码**，按名字识别为 3857，避免误报"投影方式不支持"。

- **⑤ 矢量导出（GeoPackage / Shapefile / GeoJSON）（2026-10-05）** —— 此前只能导入，数据进来出不去。新增 `internal/vector/wkb.go`（几何 → WKB，与 geopackage.go 的读取对称）+ `export.go`（三种格式导出）。
  **格式取舍**：GeoJSON 单文件最省事；GeoPackage 单文件且属性类型/精度完整（现代默认）；Shapefile 是**文件族**且限制多 → 打包成 `.zip`（.shp/.shx/.dbf/.prj/.cpg）。
  **两条贯穿原则**：
  1. **导出与导入互为逆运算**——测试把导出结果直接喂回本包的解析器验证，不靠"看起来像"判断正确性（等于用一套独立实现交叉验证字节序、定长、字段宽度这些细节）。
  2. **有损就明说**——`ExportResult.Warnings` **只承载真正的损失**（跳过的要素、被截断的字段名）。曾一度把"几何以 WKB 写出（二维）""属性表以 UTF-8 写出"也塞进提示，属于每次都弹的噪音，已删掉：前端弹出来的每一条都得值得用户看一眼。
  **实现要点**：
  - **环方向有两套相反约定**：MVT / GeoPackage(OGC 简单要素) 要求外环**逆时针（正面积）**，Shapefile(ESRI) 要求外环**顺时针（负面积）**。导出前各按目标格式归一化（`orientRing`）；弄反会让洞被当成实体画出来。`normalizeRing`（MVT）现在只是 `orientRing` 的包装，注释里写明两套约定的归属。
  - Shapefile：一个文件只能有一种几何类型 → 选主类型（`shpTypeFor`）、跳过其它类型并回显数量；点图层按"是否含多点"决定 Point(1) 还是 MultiPoint(8)；**同时写 .shx 索引**（不写的话部分软件要自建）；`.prj` 写规范 ESRI WKT（且能被本包解析器读回来，测试锁了这点）。
  - **DBF 两个坑**：① 字段名上限 **10 字节**，截断后必须按**原字段名**去查属性（`attrColumn.Src`）——按截断名查会让整张表属性落空，导出看着正常、打开才发现是空的（写了专门的回归用例）；② 字符串宽度按**字节**计，截断要落在 rune 边界上，不要劈开多字节字符；数值真溢出时按 dBASE 标准写一排 `*`，而不是悄悄截掉数字。
  - GeoPackage：真 SQLite 文件（复用 modernc 驱动），写规范三表 + `application_id`/`user_version` + 回填 bbox + `ANALYZE`；**几何类型混合时明确拒绝**（单几何列装不下，实测 `beijing_blocks`（405 面 + 5 点）导出 gpkg 返回 400 就是这个原因，属正确行为）。
  - 坐标系只支持 4326/4490/3857：写不出正确的 `.prj` / 坐标系定义时**明确报错**，绝不给一个猜的。
  接口：`GET /api/v1/vector/layers/{name}/export?format=geojson|gpkg|shp`。有损信息走响应头回传（`X-Tangis-Features` / `X-Tangis-Skipped` / `X-Tangis-Warnings`；HTTP 头只能是 ASCII，中文按 URL 编码，前端解码展示）。`RouterGateway` 补实现 `DatasetSource`（桌面装配用的正是它，否则导出会报"数据源不支持"）；PostGIS 数据源明确提示改用 WFS。
  前端：图层详情面板加三个导出按钮 + 有损提示 toast（实测弹出「已导出 beijing_blocks_shp.zip（400 个要素，跳过 5 个）」与「Shapefile 一个文件只能有一种几何类型，已跳过 5 条其它类型的要素」）。踩到一个编码细节：Go 的 `url.QueryEscape` 把空格写成 `+`，而 `decodeURIComponent` 只认 `%20`，前端需先还原。
  测试 278 → **286 PASS / 0 FAIL**（+8）：三种格式往返（导出→本包解析器读回，含带洞多边形、中文属性、整型/浮点/布尔/日期）、混合几何跳过计数、字段名截断但取值不丢（回归）、点/多点类型选择、不支持坐标系报错、`Server.ExportLayer` 全链路、环方向两套约定的断言。
  E2E：**用 Python 独立校验产物**（不依赖 Go 代码）——`sqlite3` 直读导出的 gpkg 规范表/contents/geometry_columns/坐标系定义与几何 BLOB（确认 `GP` magic + flags 0x01 + srs_id + WKB 类型）；`zipfile` 读 .shp 头（形状类型 5）/DBF 头（记录数、字段、记录宽）/首条记录的部件数（确认洞保留）/`.prj`/`.cpg`；`json` 读 GeoJSON。前端实测点击导出 → 请求 200 → 触发下载 + 提示。
  边界（如实保留）：PostGIS 数据源不支持导出；Shapefile 不保留 Z/M（本来就没解析过）；坐标系仅三种。

- **⑥ 矢量编辑（画布 + 工具栏 + 就地写回）（2026-10-05）** —— 新增 `internal/vector/edits.go`（写回）、`POST /api/v1/vector/layers/{name}/edits`、前端 `VectorEditView.vue`（画布/工具栏/属性面板）+ `utils/geoview.ts`（投影与命中判定纯函数）。
  **写回策略选型依据是"别动不该动的东西"**：
  - GeoJSON：一文件一图层 → 整体重写（临时文件 + rename 原子替换）
  - **GeoPackage：只对目标要素表做 SQL 增删改**。若图省事整库重写，同库其它要素表会被直接抹掉——数据丢失且用户很难察觉，因此专门写了"编辑一个表后同库其它表必须原封不动"的测试
  - Shapefile：重写 `.shp/.shx/.dbf/.prj/.cpg` 文件族（顺带补上原文件缺失的 `.shx`）
  **安全前提**：**首次编辑前自动备份源文件**（`<文件名>.orig`，只备份一次；后续编辑不得覆盖它——测试锁了"第二次编辑后备份内容仍是编辑前的"），备份路径随结果回显给用户。编辑是不可逆的原地写入，必须有退路。
  **其它约束**：几何类型必须与图层一致（Shapefile / GeoPackage 都是单几何类型存储，往面图层画点会写出非法文件 → 明确拒绝）；`update` 的属性是**整体替换**；GeoPackage 中未知属性键不擅自 ALTER TABLE，忽略并在 `warnings` 里说明；写回后**主动清网关缓存**（mtime+size 在秒级粒度下可能漏判，会导致"刚存完还是旧数据"）。
  **前端编辑器设计要点**：
  - **必须拉全量要素**，所以**复用导出接口**（`export?format=geojson`）而不是 WFS GetFeature——WFS 受服务端 count 上限（默认 10000）约束，拿不全会让"与初始快照做差集"算出**错误的删除**（把没加载的要素全删掉）。这是编辑器最容易埋的一个雷。
  - 工作副本 + **不可变更新**（每次改动替换要素对象）→ 撤销只需留一份数组浅拷贝快照。
  - 保存时与初始指纹（JSON 串）做差集，**只提交真正变化的要素**，避免"编辑一个点、回写一万条"。
  - 画布：Web Mercator 视口（中心 + 每像素米数），滚轮围绕光标缩放、拖拽平移、米制网格刻度；面用 **even-odd** 填充才能挖洞；MultiPolygon 保留环分组（`groups`）以便写回不丢结构；选中要素显示可拖顶点，拖内部整体移动。
  - 工具栏：平移 / 选择 / 画点 / 画线 / 画面 + 撤销 / 删除 / 全图；线面绘制双击或回车结束、Esc 取消；Delete 删选中、Ctrl/Cmd+Z 撤销；有未保存变更时 `beforeunload` 提醒。
  - 属性面板：键值可增删改，值按类型推断（数字 / true-false / 文本）。
  测试 286 → **299 PASS / 0 FAIL**：三种源格式的增删改往返、备份内容=编辑前、GeoPackage 同库其它表不受影响、几何类型拒绝、参数校验（空操作/未知操作/缺 id/缺几何/目标不存在）、Server 全链路（含"编辑后立刻读到新数据"的缓存失效断言）。
  E2E（真实浏览器）：打开编辑器 → 载入 2 个面要素、画布绘制 7.7 万像素 → 切「画面」工具 → 画三角形（合成 PointerEvent）→ 回车闭合 → 待保存 1 → 保存 → 提示「已保存：新增 1 / 修改 0 / 删除 0（现有 3 个要素）」+「源文件已备份：…/districts.shp.orig」。**独立验证**：元数据 3 要素、WFS 3 条（原有中文属性完好、新增要素无属性、新要素坐标落在合理范围）、`.dbf` 当前 3 条而**备份 2 条**、`.shp` 456→512 字节、备份文件族齐全。

- **⑦ 矢量编辑补齐：加点 / 删点 / 吸附（2026-10-05）** —— 上一轮编辑器的已知缺口（只能拖顶点，不能增删；无吸附，相邻面画不齐）。纯前端改动（编辑 API 已支持任意几何更新，后端零改动）。

  **吸附设计要点（关键）**：
  1. **吸附结果必须携带目标的原始经纬度**，不能"取屏幕坐标再反算"——后者会引入浮点往返误差，相邻面之间会留下看不出来但真实存在的缝隙（等同没吸附）。为此 `SnapTargets.vertices` 带 `lon/lat`，边按参数 t 插值。实测：把顶点拖到另一个顶点后两坐标**逐位完全相同**；插入点纬度**逐位等于**边的纬度。
  2. **顶点优先于边**：顶到顶才能严丝合缝，边吸附只保证落在线上（可能落在别人边的中间，接缝仍错开）。
  3. 阈值用**屏幕像素**（缩放后手感一致）；设为可关（总开关 + 顶点/边两个子开关）。
  4. 顶点拖动改为**绝对定位 + 抓取偏移**（`dx/dy`）——原来的增量累加会漂移，且无法保证落点落在吸附目标上。
  5. 性能：`collectSnapTargets` 先用**经纬度 bbox 粗筛**（只投影光标附近要素，投影是最贵的一步）；要素范围用 **WeakMap 按对象身份缓存**（要素不可变 ⇒ 天然失效，不需要版本号）；空闲移动用"指示器指纹"判断是否需要重绘。
  ⚠️ **本轮抓到一个会影响所有交互的真 bug（已在文档中记下诊断方法）**：编辑器画布只在 `window.resize` 时重算尺寸，但画布尺寸也会因**布局变化**而改变——我新加的「吸附」面板把侧栏撑高 → grid 行变高 → 画布从 710 变 884 CSS px，而 backing store 仍是 710 ⇒ **画面纵向拉伸 + 所有点击落点整体偏移**，表现为"点不中顶点""在边上点击却不插入"。改用 `ResizeObserver` 监听画布元素本身解决。
  **诊断方法值得复用**：不猜、不靠内部状态——① 用 `pointermove` + 读界面的经纬度读数**反解屏幕↔地理的仿射变换**（先验证 x/y 两轴比例一致，不一致就说明视口有猫腻）；② 扫描画布上顶点手柄的**白色像素簇**得到应用自己绘制的顶点位置，与计算值对比 ⇒ 一眼看出"backing store 与 CSS 尺寸不一致"（两套坐标差了 1.245 倍）。
  **完全自洽的浏览器验证**（不依赖复刻的视口数学）：探针找"确在面内且洞外"的点选中要素 → 扫描手柄像素得到顶点位置 → 用它点击/拖动 → 保存 → **直接解析磁盘上的 .shp**（绕开服务端缓存）逐位比对。结果：拖动顶点吸附后两顶点 repr 完全相同；加点落在边上（纬度逐位相等）且删点后其余角逐位保留；随后用编辑 API 把测试数据恢复原状（`updated: 2`）。
  **测试陷阱（本轮踩到并记住）**：① 带洞多边形的**质心可能落在洞里**，用它当"选择点"会落空，随后落到"整体拖动要素"分支把整个面平移了（污染过一次测试数据，靠 `首次编辑自动备份` 的 `.orig` 恢复 —— 这正是那个设计第一次派上实战用场）；② 同一 tick 连发多个 `PointerEvent` 会让交互落到意料之外的分支，必须分步 + 间隔；③ 同步读 Vue 渲染出的 DOM 会读到旧值（要等一个 tick）；④ WFS 读取可能拿到陈旧缓存 ⇒ 验证关键结论时**直接解析文件**；⑤ shell 变量里带 `[` 会被 zsh 当模式解析。
