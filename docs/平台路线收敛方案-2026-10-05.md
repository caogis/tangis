# TanGIS 平台路线收敛方案（M2'/M3'/M4'）

> 日期：2026-10-05 ｜ 前置文档：[PRD v1.1](./GISBox竞品分析与PRD.md)、[需求功能核对](./需求功能核对.md)
> 决策输入：① 路线 = **平台/服务端**（Web + Docker），明确放弃桌面壳 ② 投入 = **3~5 人小团队，周级粒度，可并行分工**
> 定位：本方案是 PRD v1.1 的**路线收敛补充**，重排 M2/M3 范围与验收，不推翻 PRD 的产品定位与 OKR。

---

## 一、为什么这么收敛

今日核对的结论是：**技术底座已就绪，产品完成度薄弱**（详见 `需求功能核对.md`）。

- 切片内核：真实 OSGB 解析、真几何 b3dm/tileset、Rayon 并行、journal 断点续切 —— **已具备**
- 服务端：NATS + PG + MinIO + Redis + 多租户/配额/防盗链 + License 框架 + WMTS/MVT/3DTiles + t3d 容器 —— **已具备**
- 薄弱点在**上层通达性**：协议不全（WMS/WCS/Terrain/点云缺）、交互缺失（无场景树/测量/可视编辑/导入 UI）、工程配套为零（无 CI / 无 Observability / 无 Helm / 未 git）

因此本方案的策略是：**不补底层，只在上层收敛出"能对外演示、能卖出去"的完成度**。所有条目都是"确定性工程量"，无技术攻坚项（Terrain/点云/LAS 均有成熟范式，编辑器交互是 Cesium 标准能力）。

## 三、目标定义：什么叫"能打"

**一句话目标**：一个测绘院 / 集成商的技术负责人，能在 30 分钟内自己把一份 OSGB 数据变成可加载的 OGC 服务，并在浏览器里看、量、查、转 —— 全程只用浏览器和一条 `docker compose up`。

**对外 demo 验收清单（每次里程碑出口逐条打勾）**

1. 拖/选一个 OSGB 目录 → 自动识别格式与坐标系 → 一键建任务
2. 任务列表看得到进度、能重试、能取消、能下日志
3. 质检报告可读（裂缝/悬浮/退化/法线/自相交）
4. 产物一键发布为 **3DTiles / WMTS / TMS / MVT / WMS / WCS / Terrain** 七选一，出即拿 URL
5. Cesium 里能看：**场景树**（图层开关 + 定位）、**属性查询**、**测量**（距离/面积/高程）
6. 影像底图 + 第三方 WMTS 叠加
7. 防盗链签名 + 审批 + 配额可见（管理员界面）
8. Grafana 面板看得到 QPS/延迟/任务成功率
9. `docker compose up` 一键起；Helm 一键上集群
10. 5GB OSGB @16 核实测 ≤30min（不再是外推）

## 六、并行协作约定（3~5 人同动三栈，先立规矩）

1. **契约先行**：任何新 HTTP 接口必须先改 `docs/openapi.yaml`（已有双向漂移测试 `api/openapi_test.go` 守护）；内核新增 CLI 子命令先写 `--help` 与参数 JSON schema，Go 侧再对接。
2. **瓦片元数据契约**：影像/地形产物必须输出 `metadata.json`（现有 xyz.rs 已有），新增 Terrain 时补 `layer.json`，服务端靠它生成 Capabilities —— 先定 schema 再写两端。
3. **分支纪律**：建议现在立刻 `git init` 并采用短分支（≤3 天合并） + PR 模板；因为尚未纳入版本控制，这是当前最大风险（见下）。
4. **每日demo制**：由于界面变化快，建议每天一个可访问环境（CI 产物或固定端口），避免期末集成。
