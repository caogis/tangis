# 《GISBox 竞品分析与 PRD》专家评审报告

> 评审日期：2026-10-03 ｜ 评审对象：docs/GISBox竞品分析与PRD.md v1.0
> 评审形式：三专家会审（GIS 行业专家 / 软件架构专家 / 产品商业专家）
> 结论：**原则通过，需修订后进入 M1**。共识别 4 个高危问题、若干中低风险，修订清单见文末。

---

## 一、三位专家共同认可的部分

1. **架构代差判断正确**：分块 Manifest + 无状态 Worker 的分布式切片 + 断点续切，是对 GISBox 单机串行架构的有效胜负手（三位专家一致）。
2. **竞品分析扎实**：付费墙边界、定价矩阵、生态绑定分析信息密度高，机会点 P1-P5 论证成立。
3. **开放标准策略正确**：产物全部走 3DTiles 1.1 / OGC 标准、拒绝私有锁定，符合行业趋势。
4. **部分风险处理务实**：RVT 走 IFC 中转、信创 UOS/ARM64 与国密适配意识到位。

## 二、高危问题（必须修订）

| # | 问题 | 来源 | 详述 |
|---|---|---|---|
| H1 | **测绘合规完全缺失** | GIS 行业 | 对外发布地图服务需互联网地图服务测绘资质；DEM/地形保密技术处理（高程抽稀、坐标偏移）、CGCS2000 七参数（保密参数）托管、GCJ-02 纠偏与天地图接入均未提及。对测绘院客户这是**准入项**而非可选项 |
| H2 | **大 B 客户打法缺失 + 变现闭环断裂** | 商业 | GISBox 有中电科/商汤级客户 + 测绘资质 + 山海鲸生态；我方 M3 才启动商业化等于让出政企市场。"协同免费不限席位"自断现金牛（对标其 ¥3999/年已验证付费点） |
| H3 | **工程量严重乐观 + 团队假设缺失** | 架构 | Rust 内核 + Go 服务 + Tauri + CRDT + WebGPU 总量约 15-20 人年，PRD 无团队规模假设；若 <5 人，双语言边界维护成本将吞噬迭代优势。OSGB→3DTiles 核心难点（LOD 重建、父子聚合、纹理 atlas）GDAL/3d-tiles-tools 均不覆盖，M1"复用"策略不成立 |
| H4 | **验收指标不可测/自相矛盾** | 三方共识 | 摘要"快 10 倍" vs F-02"≤GISBox 耗时"矛盾；"200 万面/分钟"无统计口径（LOD 级别、是否含纹理压缩）；WMTS P99<100ms 需二级缓存支撑 |

## 三、中风险问题

| # | 问题 | 详述 |
|---|---|---|
| M1 | 标准表述错误 | 1.2 节"S3M/I3S 国标格式"有误：I3S 是 OGC 社区标准，S3M 才是行业标准；3D Tiles 3DGS 扩展仍是 Cesium 提案未定稿，F-11 排 P1 与风险表自相矛盾 |
| M2 | GPL 传染风险 | LibreDWG 为 GPLv3，与"开源内核 + 商业授权"模式存在冲突，"明确使用条款"不够，需进程隔离或收缩为 DXF 优先 |
| M3 | 分布式切片遗漏存储瓶颈 | 高吞吐下 MinIO PUT 压力与瓦片写放大未评估；跨分块 LOD 合并需读邻居分块，与"任意 Worker 续跑任意分块"声明冲突，缺调度亲和性设计 |
| M4 | WebGPU headless 未论证 | 云服务器普遍无 GPU，wgpu surfaceless 退化为软渲染；桌面壳 WebView 的 WebGPU 成熟度也存疑 |
| M5 | 范围失控 | F-08 增量写回、F-16 CRDT 场景协同均为"人年级"难题，M2/M3 承诺过重 |
| M6 | PRD 结构缺章节 | 无 OKR/成功指标（北极星=付费团队数）、无 TAM/SAM、无用户画像（测绘院 vs 集成商差异大）、无我方定价表（附录只有对方价） |
| M7 | 市场风险盲区 | 未覆盖 GISBox v2.2.x 持续迭代的反扑、山海鲸生态导流、开源被云厂商白嫖风险 |
| M8 | 队列选型摇摆 | NATS JetStream 与 Redis Stream 并列出现，未按持久化/重放需求收敛 |

## 四、修订行动清单（按优先级）

1. **新增 P0「测绘合规模块」**（F-21）：CGCS2000 转换与七参数托管、DEM/地形脱密、发布审批与水印、互联网地图服务资质路径说明。
2. **商业化前置**：M1 即设计 Open Core 分界与 License 校验；M2 上线时同步发布定价表 + 3-5 家测绘院设计伙伴共创；协同改为"开源版限 3 席位 + 商业版不限"。
3. **重排优先级**：数据质检（裂缝/悬浮/拓扑）、坐标转换、轻量化、脱密是测绘生产刚需，应高于 CRDT 协同（F-16）与 WebGPU（F-18）；F-11（3DGS）降为 P2 实验特性，跟随标准定稿。
4. **补团队规模章节并给 A/B 方案**：≥8 人维持 Go+Rust 双语言；<5 人收敛为全 Go（切片性能用 C 扩展/cgo 补）或全 Rust。
5. **验收指标改绝对值**：如"5GB OSGB @16 核 ≤30min"，自建公开基准数据集，删除"快 10 倍"表述。
6. **分布式切片补设计**：切片产物先落本地 NVMe、异步批量上传 MinIO；分块按 LOD 拓扑排序 + 调度亲和性；WMTS 给出 Redis→本地盘两级缓存的 P99 分解预算。
7. **DWG 策略收缩**：DXF 优先，LibreDWG 以独立进程隔离 GPL；ODA SDK 作商业版选项。
8. **PRD 补章节**：OKR（北极星指标）、我方定价表、用户画像、市场规模、市场风险（含 GISBox 反制预案）。

## 附：三位专家原始评审意见

### 评审 A —— GIS 行业专家

**✅ 认可**：分块 Manifest 架构正确；开放标准优先正确；RVT/IFC 与 DWG 风险策略务实；信创与国密适配到位。

**⚠️ 问题**：① 测绘合规硬门槛全缺（资质、DEM 脱密、七参数保密、GCJ-02/天地图）；② 3DGS 扩展未定稿却排 P1，S3M/I3S 表述错误；③ LibreDWG GPL 传染冲突低估；④ F-02 验收以竞品为基准不可测；⑤ 增量写回与 CRDT 协同为超级难题，承诺过重。

**💡 建议**：新增测绘合规模块（P0）；3DGS 降 P2、RVT 收缩 IFC 路线；DWG 收缩 DXF 优先；绝对指标 + 自建基准集；按生产刚需重排优先级（质检/坐标转换/轻量化/脱密 > 协同/WebGPU）。

### 评审 B —— 软件架构专家

**✅ 认可**：无状态 Worker + 断点续切方向正确；开放标准输出正确；渐进式交付节奏（M1 单机 → M3 集群）合理。

**⚠️ 问题**：① 无团队假设，双语言 15-20 人年收益比存疑；② 3d-tiles-tools 是 Node 工具链不能嵌入 Rust 内核，OSGB 核心难点必须自研，工程量乐观；③ 遗漏 MinIO 写放大与跨分块 LOD 合并的调度冲突；④ WebGPU headless 无 GPU 时性能塌方；⑤ 吞吐口径未定义、指标不自洽；⑥ 队列选型摇摆。

**💡 建议**：补团队章节（<5 人收敛单语言）；产物落本地 NVMe 异步上传；桌面版以 WebGL2 为主；公开 benchmark 替代"快 10 倍"。

### 评审 C —— 产品商业专家

**✅ 认可**：竞品拆解与付费墙分析扎实；架构代差选点准确；法律与工程风险处理务实。

**⚠️ 问题**：① 【致命】大 B 打法缺失，开源模式对政企无说服力，M3 商业化太晚；② 【严重】变现闭环断裂，"协同免费"自断现金牛；③ 【严重】缺 OKR/市场规模/用户画像/我方定价表；④ 市场风险盲区（GISBox 反扑、生态捆绑、云厂商白嫖）；⑤ "快 10 倍"无基准。

**💡 建议**：Open Core 分界与 License 机制 M1 落地；M2 同步发布定价 + 设计伙伴客户；协同改为限席位双轨制；大 B 走"企业版 + 资质 + 私有化交付"路线；北极星指标 = 付费团队数。
